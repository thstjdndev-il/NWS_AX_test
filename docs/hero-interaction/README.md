# 바이브코딩 캠프 랜딩 · Hero 인터랙션 명세

랜딩 페이지 첫 화면(Hero)의 인터랙션 명세예요. 프롬프트에 아이디어가 입력되고 전송되면, 그 서비스의 화면들이 렌즈 왜곡 갤러리로 퍼져 나오며 메인 카피가 떠올라요.

> 핵심 메시지: **"내 아이디어 → 실제로 배포된 내 서비스"**. 첫 화면에서 "나도 만들 수 있겠다"를 체험하게 하는 게 목표예요.

## 4. 렌즈 갤러리

### 원리

1점 투시(각 이미지를 사다리꼴로 기울이기)가 **아니에요.** 이미지들은 평평한 한 줄의 띠에 놓여 있고, 화면의 모든 픽셀을 **볼록렌즈처럼 연속으로 휘어서** 그려요. 그래서 띠의 윤곽과 이미지 속 가로선이 곡선으로 휘어요.

화면 좌표 → 평평한 띠 좌표로 역변환해서 텍스처를 읽는 방식이에요 (프래그먼트 셰이더). 렌즈 중심에서 띠 방향 거리를 `a`, 수직 방향 거리를 `c`라고 하면:

```
xd = a / R                                  // 정규화된 화면 거리
xu: xu * (1 + KX * xu²) = |xd| 를 뉴턴법으로 풀기   // 띠 방향으로 퍼짐
ymag = 1 + K * xu⁴                          // 바깥으로 갈수록 수직 방향으로 부풂
s  = xu * R / g                             // 평평한 띠 위의 거리
yu = c / ymag / g                           // 평평한 띠 위의 수직 위치
```

- `g`는 펼침 진행도(0.15 → 1)예요. 펼침 중에는 `K`와 `KX`도 함께 커져요 (`K × (0.25 + 0.75p)`, `KX × (0.4 + 0.6p)`, p = 곡선 적용 진행도).
- 띠 위의 칸 번호 `n = floor(s / SLOT − flow)`, 칸 안 위치로 이미지와 모서리를 정해요. `flow`가 계속 증가해서 이미지가 바깥으로 흘러가요.
- 왼쪽(또는 위쪽) 이미지는 좌우(상하)가 뒤집히지 않도록 텍스처 좌표를 보정해요.

정확한 구현은 `prototype/index.html`의 `FS`(프래그먼트 셰이더)와 `drawGallery()`를 그대로 참고하면 돼요.

### 확정값

| 값 | 데스크톱 | 모바일 | 설명 |
|---|---|---|---|
| 방향 | 좌우 | **상하** | 띠가 놓인 방향 |
| 렌즈 중심 | (720, 449.6) | (195, 493) | 프롬프트 중심 |
| R (정규화 거리) | 720 | 440 | |
| 왜곡 강도 K | **36** | 36 | 수직 부풂 |
| 퍼짐 KX | 2.0 | 2.0 | 띠 방향 퍼짐 |
| 가운데 높이 h0 | **110** | 110 × 1.3 = 143 | 평평한 띠의 이미지 높이(폭) |
| 칸 길이 SLOT | 56 | 56 × 1.3 = 72.8 | 평평한 띠의 칸 간격 |

## 7. 구현 체크리스트

- [ ] 인트로(01~03)는 페이지 진입 시 한 번만 재생
- [ ] 갤러리 흐름은 계속 재생하되, 화면 밖이거나 탭이 숨겨지면 멈추기 (`IntersectionObserver`, `visibilitychange`)
- [ ] `prefers-reduced-motion` / WebGL 미지원 시 정지 화면으로 대체
- [ ] 캔버스 해상도는 `devicePixelRatio`에 맞추되 최대 2배로 제한
- [ ] 헤드라인·서브 카피·버튼은 실제 텍스트로 (검색·접근성). 가짜 커서와 갤러리 캔버스는 `aria-hidden="true"`
- [ ] 한국어 줄바꿈 `word-break: keep-all`
- [ ] 프로토타입의 조율 UI(슬라이더, 곡선 편집기, 재생 버튼)와 `window.__hero` 훅은 제거
